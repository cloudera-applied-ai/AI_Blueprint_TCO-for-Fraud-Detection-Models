# ai/ — the AI layer (agent · notebooks · model serving)

The intelligence of this accelerator: a ReAct-style tool-calling **agent** for natural-
language fraud analysis, backed by the XGBoost model's in-process scoring + SHAP
explanations.

## What goes here

| Path | Contents | Automated by |
|------|----------|--------------|
| `agents/agent.py` | The ReAct loop — up to 5 tool-calling rounds per question, with PII masking (`pii_mask.py`) before anything reaches the LLM. | imported by `app/backend/api.py` |
| `agents/tools/` | The 10 fraud-analysis tools: query transactions, score a transaction, explain a prediction (SHAP), risk dashboard, threshold analysis, alert patterns, merchant investigation, fraud-network tracing, drift monitoring, retraining. | `agents/tool_registry.py` |
| `agents/llm_client.py` | OpenAI-compatible client for **Cloudera AI Inference / vLLM / Ollama** — provider + endpoint from `config/config.yaml` (env-overridable). | — |
| `agents/cost_estimator.py` · `agents/pricing_fetcher.py` | The live token-cost calculator (per-conversation cost, GPU-preset comparisons, live pricing cache). | — |
| `agents/prompts.py` | The system prompt and tool-use protocol. | — |
| `notebooks/` *(add as needed)* | Interactive walkthroughs of the pipeline/model. | CML sessions |
| `inference/` *(see note)* | Placeholder — this app serves the model **in-process** from [`../app/backend/model_serving/`](../app/backend/model_serving/) (`model_utils.py` scoring + SHAP `pred_contribs`; `predict.py` is the CML model-endpoint wrapper if deployed standalone). | CML Models (optional) |
| *(repo root)* `models/` | Pipeline outputs: `xgboost_fraud.json`, `preprocessor.pkl`, `feature_names.json`, `metrics.json`, `experiments/`. Stays at root: CWD-relative contract (see [ADR-001](../docs/architecture/ADR-001-dashboard-design-system.md)); gitignored, regenerated by task 5. | `pipelines/model_training/` |

## Conventions

- Every served model gets a **model card** in
  [`../governance/model-cards/`](../governance/model-cards/).
- The agent's tools call the same code paths as the dashboard (`model_serving`,
  `experiment_runner`) — one implementation, two front doors.
- LLM credentials live in the gitignored `config/config.yaml` (or `.env`) — never in code.
- SHAP uses XGBoost's native `pred_contribs` (GPU-capable), not the CPU-only `shap`
  TreeExplainer — keep it that way when touching explanations.

The agent is wired into the app via [`../app/README.md`](../app/README.md); model training
lives in [`../pipelines/`](../pipelines/).
